## Project overview

Recent Google Reviews is a Chrome (Manifest V3) extension, with no backend, that adds a badge next to Google's all-time rating on Google Search and Google Maps place pages. The badge shows the average of the reviews from the last week, month, 3 months, 6 months (default) or year. Clicking it opens a lookalike of Google's reviews modal that lists only the reviews counted, with a dropdown to change the window. It never changes Google's own rating. It runs entirely in the user's browser as a content script on Google Search (`/search`) and Maps (`/maps`) pages only.

## Tech stack

- Plain JavaScript (ES modules, no framework, no build step to load the extension); Chrome Manifest V3, permission `storage` only
- Tests: Node's built-in test runner with `jsdom` (the only dependency)
- Architecture: Clean Architecture, dependencies point inward only (see below)


## How to run and test

- Install: `npm install`
- Tests: `npm test` (runs `node --test "test/*.test.js"`; includes an architecture test that fails on layer violations)
- Build the store upload: bump `version` in `manifest.json` (and `package.json`), then `npm run package` writes `dist/recent-reviews-<version>.zip` (manifest, PNG icons, `src/`, `styles.css` only; `dist/` is build output)
- Load the extension: `chrome://extensions` → Developer mode → Load unpacked → this folder; after code changes click Reload there and refresh the Google tab
- Visual iteration without Google: serve the folder statically (no-cache) and open `dev/demo.html`, a harness with a Google-like page and a fake streaming review loader

## Telemetry and alarm awareness

Treat this as a standing instruction, not a placeholder. When a change in this repo adds, moves, or touches a metric emission, an error log level, or an alarm definition, say — without being asked — whether the signal can fire when nothing is actually wrong, and name the alarm that consumes it (or state that none does yet).

The recurring false positive to rule out first: an error, failure, or `5xx` counter on a code path reachable by **client-driven cancellation** — a client disconnect, navigate-away, proxy/CDN abort, or upstream client timeout. In Go that is a request-scoped `context.Canceled` reaching the emitter. Guard it with `errors.Is(err, context.Canceled)` **at the emit site** (a post-handler wrapper cannot retract a metric already emitted into a process-wide buffer), and keep counting `context.DeadlineExceeded` — a timeout we set and blew is a real signal.

The full rule lives here: see `.claude/rules/backend/telemetry-noise.md` (Cursor: `.cursor/rules/backend/telemetry-noise.mdc`), plus section 6 of the always-apply agent-behavior rule.

This repo has no metrics pipeline, error counters or alarms (a client-side extension), so nothing here applies today. If telemetry is ever added, follow the rule above.

## Project-specific gotchas

- **Layers** (imports point inward only): `src/domain` ← `src/usecases` (+ `ports/`) ← `src/adapters` (`dao/`, `presenters/`) ← `src/frameworks` (`content/`, `ui/`, `popup/`). No DOM or `chrome.*` in `domain` or `usecases`. All knowledge of Google's markup lives in `adapters/dao/GoogleDomReviewDao.js` and `GoogleReviewsLoader.js`; patch those when Google changes its DOM.
- **No class names from Google**: the DAO finds stars, review cards and the headline by `aria-label`, structure and text, because Google's classes are obfuscated and change.
- **MV3 loading**: `loader.js` dynamic-imports the controller via `chrome.runtime.getURL`, so every module the content script imports must be listed in `manifest.json` `web_accessible_resources` (a test enforces this).
- **Google enforces Trusted Types**: build DOM with `createElement` / `textContent` only, never `innerHTML`.
- **Never show a number computed from a partial load.** Only a finished load counts (`RatingSummary.complete`): while loading, or when only the few snippets Google Maps shows on its Overview tab are on the page, the badge and modal show skeletons, and results appear all at once. `BackgroundLoadController` runs the load by itself once per place; when nothing will calculate it, the badge shows a click-to-calculate pill instead of a skeleton that would look stuck. Opening the modal when a result already exists is instant (`LoadReviewsUseCase.freshResult`). Never run two loads at once: the modal calls `stop()` on the background one first. **A load is never cancelled by the user.** There is no abort on scroll/click/key and no stand-down for a scrolled panel; closing the modal mid-load only hides it (`ReviewsModalController.detached`): the load finishes, `release()` puts Google's page back, and `isBusy` (open *or* detached) keeps the background controller from starting a second load meanwhile. Only a different place (`#movedOn`) or the modal taking over stops a background run.
- **The badge is a three-cell trend strip** plus an overall-direction icon, drawn from one read of the reviews (`CalculateRecentRatingUseCase.executeAll`). Its windows come from the user's "longest window" setting (`maxMonths`, whole months 2 to 11, default 6; 12 is impossible because Google says "a year ago" from 12 to 23 months): `trendWindowsFor(max)` = a month, half of max rounded up, max (a week replaces the month when the middle one is already a month, i.e. max 2): 6 → 1/3/6, 5 → 1/3/5, 4 → 1/2/4, 3 → 1/2/3, 2 → 1W/1/2, 11 → 1/6/11. Windows are generated (`N_MONTHS`, 1 to 11, plus `1_WEEK`); the old `1_YEAR` id is an alias of `11_MONTHS` and is migrated when settings are read. The load always reaches back at least as far as the longest cell (`loadWindowFor`), whatever window the modal shows, so every cell is filled; raising the setting on a page that is already calculated shows the longer windows as partial until the page is loaded again. Icons are inline SVG built with `createElementNS`; the trend rules (`overallTrend`: 3-review minimum, 0.1 steady band, judged against the longest window shown) live in the presenter. Clicking a cell opens the modal on its window.
- **Google's phone layout is unsupported on purpose** (`frameworks/content/googleLayout.js`, user agent contains "Mobi"): there the review count is a link that *navigates* to a new search (`q=… reviews`) with the list inline in the page, no dialog, so the loader's "open the overlay" step finds nothing and driving it would only move the user away. The controller renders the "Recent-only rating · open on desktop" note (one line at 360px; keep it ≤ 40 characters) (`state: 'unsupported'`) and never calls the background load. Narrow desktop windows still get the desktop layout.
- **Skeletons must not shift the layout.** Draw the real element with placeholder text from the presenter (`placeholder` in the view model) and let CSS hide the glyphs and shimmer inside the same box (`.rgr-skel-text`, `.rgr-skel-star`). Never size a skeleton with fixed widths/heights; a test enforces it. Measure the loading and loaded boxes: the difference should be 0.
- **"No more reviews" must be earned.** Google sometimes gives nothing new for a few seconds (a slow re-sort swaps the list for 10 different reviews of the same count; a background tab is throttled). `GoogleReviewsLoader.loadMore` counts *unseen ids* as growth, and `LoadReviewsUseCase` calls a list exhausted only when nearly all of `allTimeReviewCount` is loaded (or Google gave no count); otherwise it retries twice and returns `stalled`, which is never marked complete (the badge then shows the click-to-calculate pill, the modal offers "Load more reviews"). The background load also waits while the tab is hidden. Never present the first page as a result.
- **A window is only as good as what was loaded.** `RatingSummary.covered` (`domain/services/ReviewCoverage.js`, `windowIsCovered`) is true when a loaded review is older than the window (list in age order) or the whole list is loaded (needs Google's total: no total, no proof). The presenter marks uncovered windows `partial` (dotted underline, tooltip, aria) and `overallTrend` ignores them. Busy places hit the page cap, and so would a list where "Newest" never got selected (not in age order, never "covered"). The background load asks for 30 pages (`BACKGROUND_MAX_ROUNDS`); the modal keeps 12 and offers "Load more reviews".
- **The "page is paused" notice** (`LoadingNoticePresenter` + `LoadingNoticeRenderer`, driven by `ContentScriptController.syncNotice`) explains the pause, and why the extension scrolls the page instead of using paid APIs, for as long as the badge shows its "calculating" skeleton (so from the first paint of the badge, before the load has reached Google's page) and the modal is not open (a modal closed mid-load brings it back). Three traps: it is `role="alertdialog"`, never `dialog` (the loader treats any non-own `[role="dialog"]` as Google's and the quiet CSS hides it); `data-rgr-notice` must stay in all three `OWN_UI` lists; and it shields pointer events and Escape (except `rgrSynthetic`) like the modal, because one "outside" click closes Google's hidden dialog and breaks the load. It has no dismiss control and Escape/Tab/clicks do nothing: it closes when the calculation ends, or after 10 s (`NOTICE_TIMEOUT_MS`, kept by the controller) so a long run cannot trap the page. Nothing cancels the load. If the loader ever stops scrolling Google's page, the copy's reasons stop being true.
- **Icons are PNG** (Chrome's manifest ignores SVG): `icons/icon-{16,32,48,128}.png`, rendered from `icons/icon.svg` (gold star with the badge's own green "up" trend arrow, used at 48/128) and `icons/icon-small.svg` (same idea with a bolder arrow and no halo-thin strokes, used at 16/32 where the 2-unit arrow is a hairline). The arrow points are copied from `BadgeDomRenderer`'s up icon: keep them in step if that changes. Edit the SVGs and re-render all four PNGs together.
- **The badge is never drawn inside Google's own reviews dialog** (Search's "N reviews" overlay, opened by the user or by our loader). `GoogleDomReviewDao.#pickHeadline` still reads the rating and count from the dialog's headline when it is open (its count is the list's own, which the "is the list finished" checks rely on), but `row`, the badge anchor, is the place panel behind it, or null (no badge) when the dialog is the only headline on screen.
- **On/off is per kind of page**: `searchEnabled` and `mapsEnabled` (both default on), not one switch. `ContentScriptController` picks the flag from the URL on every update (`isMapsPage`; Google can move between Search and Maps without a reload) and takes the badge, the notice and the automatic load down when its flag is off. The old single `isEnabled` key is still read, so someone who had it off keeps both off, but it is never written again (`READ_KEYS` in `ChromeStorageSettingsDao`); a flag set on its own always wins over it.
- **Keep the manifest's site access narrow.** The content script matches only `https://www.<google domain>/search*` and `/maps*` (six domains), and `web_accessible_resources` only those origins; `test/manifest.test.js` fails on a wildcard host or scheme. A broad `*://*.google.com/*` makes the Chrome Web Store warn about an in-depth review (and ran the script on Gmail/Docs). The trade-off: a page Google reaches by client-side navigation from a non-matching URL does not get the script until it loads fully; Search results and Maps do load fully in practice.
- **The loader never clicks a real link.** Desktop Search opens its overlay from `<a role="button" href="#…">`; an opener whose href leaves the page (`#navigates`) is skipped, because clicking it would navigate away from the place.
- **Maps empties its review list after "Newest".** Choosing the sort empties the list for ~200 ms and then refills it, so the loader waits for the Sort control to exist, treats "the list is non-empty and its ids changed" as the sort having applied, and `loadMore` waits for an empty list to refill instead of reporting "no growth" (which, retried back to back, produced a false `stalled` and the idle pill on Maps).
- **Place identity** (`placeKey`) is the Maps place id from the URL (`!1s0x…:0x…`) when there is one, else the place *name*, never the review count: Google shows a different count in its reviews dialog than on the page, so a key with the count in it discards the finished result when the dialog closes. The name alone is not enough on Maps because branches of a chain share it (moving between two Starbucks would keep the first one's reviews and result, and skip the automatic calculation); the id also survives the Reviews tab, where the name is not readable. The key travels with the snapshot into `RatingSummary.placeKey`, which `BackgroundLoadController` uses to decide "another place".
- **Theme** (`frameworks/ui/uiTheme.js`): Google Search follows the system light/dark setting, so the badge, tooltip and modal do too; Google Maps has no dark mode on the web, so all of it is pinned to light. Never infer the theme from page backgrounds. The modal also keeps one fixed size in every state, so the loaded modal is exactly the skeleton's size.
- **Only loaded reviews count** (12 pages per run; "Load more reviews" continues). Google's dates are coarse ("2 weeks ago").
- **Testing against live Google**: bundle with esbuild and paste into the page; a localhost fetch is blocked by Google's CSP.
